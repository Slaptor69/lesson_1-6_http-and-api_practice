# Backend: учебный API

В этой папке находится минимальный API для практики. Мы не пишем полноценный backend: `json-server` читает `db.json` и автоматически создает HTTP-маршруты.

## Блок 1. Запуск и исследование API — 10 минут

### 1.1 — Найдите источник данных

Откройте `db.json` и ответьте:

1. Как называется ресурс верхнего уровня?
2. Сколько объектов находится в массиве?
3. Какие поля есть у одной заявки?
4. Какой URL должен вернуть весь массив?

Имя свойства `applications` становится частью маршрута:

```text
http://localhost:3000/applications
```

### 1.2 — Установите зависимость

Откройте терминал в папке `backend` и выполните:

```bash
npm install
```

После команды появится папка `node_modules`. В ней находится код установленных пакетов; редактировать и загружать ее в Git не нужно.

Проверьте `package.json`:

- `devDependencies` фиксирует используемую версию `json-server`;
- `scripts.dev` хранит команду запуска;
- `package-lock.json` фиксирует точные версии зависимостей.

На этом занятии устройство npm глубже не разбирается: он используется как способ получить и запустить готовый инструмент.

### 1.3 — Запустите сервер

```bash
npm run dev
```

Оставьте процесс запущенным. Откройте в браузере:

```text
http://localhost:3000/applications
```

**Ожидаемый результат:** браузер показывает JSON-массив из трех заявок, а терминал сообщает о запросе `GET`.

### 1.4 — Проверьте связь файла и API

Добавьте в массив `applications` четвертый объект с уникальным `id` и собственными данными. Сохраните `db.json` и обновите страницу API.

Пример формы объекта:

```json
{
  "id": "4",
  "name": "Ваше имя",
  "email": "student@example.com",
  "topic": "Городская мастерская",
  "createdAt": "2026-10-11T16:30:00.000Z"
}
```

Следите за JSON-синтаксисом: между объектами должна быть запятая, а после последнего объекта — нет.

**Видимый результат:** после сохранения новый объект доступен по двум адресам:

```text
http://localhost:3000/applications
http://localhost:3000/applications/4
```

## Карта API на занятие

| Действие | Метод | URL | Тело запроса | Ожидаемый статус |
| --- | --- | --- | --- | --- |
| Получить все заявки | `GET` | `/applications` | нет | `200 OK` |
| Получить одну заявку | `GET` | `/applications/:id` | нет | `200 OK` |
| Создать заявку | `POST` | `/applications` | JSON | `201 Created` |

### Маршруты дополнительной части

Эти действия не нужны для обязательных пяти блоков.

| Бонусное действие | Метод | URL | Тело запроса | Ожидаемый результат |
| --- | --- | --- | --- | --- |
| Отфильтровать по теме | `GET` | `/applications?topic=...` | нет | массив подходящих заявок |
| Удалить заявку | `DELETE` | `/applications/:id` | нет | успешный ответ `2xx` |
| Изменить заявку | `PATCH` | `/applications/:id` | JSON с изменениями | обновленный объект |

Полный базовый адрес:

```text
http://localhost:3000
```

## Быстрая проверка блока 1

- `npm install` завершился без ошибки;
- `npm run dev` не завершился и продолжает держать сервер;
- `/applications` возвращает массив;
- `/applications/1` возвращает один объект;
- дополнительная запись из `db.json` появилась в ответе;
- вы можете показать метод, URL, статус и тело ответа.

После проверки переходите к [frontend/README.md](../frontend/README.md).

## Если сервер не запускается

### `npm: command not found`

Node.js и npm не установлены или терминал не видит их. Сообщите преподавателю — не тратьте практику на переустановку среды.

### Требуется более новая версия Node.js

Проверьте:

```bash
node --version
```

Для подготовленной версии проекта нужна Node.js `22.12` или новее.

### Порт 3000 занят

Остановите старый процесс в его терминале сочетанием `Ctrl+C`, затем снова выполните `npm run dev`.

### Браузер показывает `404`

Сравните URL с именем массива в `db.json`. Маршрут называется `/applications`, а не `/application`.
